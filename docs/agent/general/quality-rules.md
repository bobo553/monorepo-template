# 工程质量专项规范

## 调试与缺陷修复

- 先稳定复现并记录最小输入、环境、版本和完整错误链，区分事实、假设与未验证信息。
- 每轮验证一个可证伪假设；修复根因，不以吞异常、无界重试或扩大超时掩盖问题。
- 缺陷修复补充失败用例并验证相邻回归。无法自动化时记录人工步骤、结果和剩余风险。

## 测试策略

- 纯规则使用单元测试，真实边界使用集成/契约测试，少量关键用户链路使用 E2E。
- 测试应确定、隔离、可重复，覆盖正常、边界、拒绝、重复、取消、超时和部分失败。
- Mock 只替代明确端口，不能用 Mock 证明数据库约束、浏览器行为或第三方协议兼容。
- 覆盖率用于发现盲区，不为提高数字编写无断言或只验证实现细节的测试。

## 评审与重构

- 依次检查目标与范围、正确性、安全与隐私、边界、可维护性、性能、测试和可运维性。
- 大改动拆成可独立验证的阶段；机械迁移与行为改变尽量分开。
- 重构前用现有测试或特征测试锁定行为；只在重复代码具有相同语义和变化方向时抽象。
- 删除代码前检索动态入口、配置、消费者和迁移窗口。

## 文档与依赖

- 文档中的命令、路径、版本和输入输出应可执行或可验证；同一事实只保留一个权威来源。
- 示例使用虚构或脱敏数据，不包含真实凭据、个人信息或危险命令。
- 引入依赖前评估维护状态、发布来源、许可证、体积、安全记录和替代方案。
- 依赖版本与锁文件必须一并评审；CI 使用冻结锁文件。
